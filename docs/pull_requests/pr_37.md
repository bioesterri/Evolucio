# PR-37 — Checkpoints i snapshots amb Zarr

Branca: `pr-37/zarr-checkpoints-snapshots`.

Els runs registrats poden guardar checkpoints reprenables i snapshots analítics
com a stores Zarr 3 independents. El scheduler divideix els chunks per arribar
exactament als intervals absoluts, sense canviar la simulació ni els seus hashes.

- Checkpoint: 41 arrays del carry complet, amb slots inactius, els quatre tensors
  del GenomeBatch, comptadors d'IDs, clau RNG tipada threefry2x32 i tots els camps
  del MetricsAccumulator. Reconstrueix els PyTrees reals, no dicts NumPy.
- Snapshot: reutilitza SimulationSnapshotDTO del PR-31, amb 13 arrays analítics,
  només agents vius en ordre canònic, món complet i dtypes preservats. No inclou
  RNG, pesos neuronals ni acumuladors i no existeix una conversió per reprendre'l.

Els dos schemas tenen noms i versions independents. Restore valida hashes,
config_hash i CompileSignature esperades, digests del core, formes, dtypes i
invariants estructurals PR-26. Rebutja incompatibilitats sense force, migracions
ni reparacions. Els acumuladors es preserven, inclosos valors signats legítims.

Cada store s'escriu a un temporal, es verifica i es renomena al nom immutable
`step-<state.step>.zarr`. El catàleg intern d'integritat i l'índex extern guarden
identitats SHA-256 calculades en streaming sobre paths i bytes. Detecta captures
absents, corrupció, incompatibilitats i stores orfes sense adoptar-los. Els
fitxers aliens no catalogats no formen part de la identitat.

L'índex Zarr s'actualitza atòmicament; el manifest PR-35 només registra index.json.
Les captures coexisteixen amb Parquet PR-36: els checkpoints conserven carry per
al futur, Parquet conserva la història analítica. Les fallades retenen captures
anteriors i publiquen l'índex parcial. keep_last_checkpoints elimina captures
antigues només després d'indexar el checkpoint nou; mai elimina snapshots.

La continuació host amb source_checkpoint crea un run_id nou i registra
source_run_id, source_checkpoint_step i source_checkpoint_hash. Manté el step
absolut i l'acumulador original. No modifica el run d'origen ni promet resume
transaccional del mateix run, rollback de Parquet o recuperació distribuïda.

CLI: intervals i flags finals explícits, dry-run sense compilació ni stores,
checkpoint list/verify i snapshot list. La verificació local incorpora Zarr.
Zarr ja estava declarat com a extra; es reutilitza el rang >=3.0,<4 i la versió
3.2.1 del lock com a dependència base per a la funcionalitat CLI integrada.

Documentació: `docs/reference/zarr_checkpoints_snapshots.md`.

## Validació

La suite prèvia a la implementació passa: **872 proves**.
La prova principal executa 0→100 i compara amb checkpoint/restore/continuació als
punts 1, 17, 32 i 40. L'escenari inclou conflictes de moviment, alimentació,
naixements, mutació i morts. Compara el carry immediat restaurat bit a bit i el
futur segons PR-29, inclosos RNG, IDs i acumuladors.

També es cobreixen captures amb chunks 4/7, sampling Parquet independent,
config/signature incompatibles, corrupció, paths, retenció, extinció, snapshots
no reprenables, tots els modes, CLI i continuació sense snapshots d'origen.

Resultats finals:

- `uv sync --group dev`, `uv sync --locked --group dev`, `uv lock --check` i
  `uv pip check`: correctes.
- `uv run pytest`: **928 passed** en la passada completa estàndard; les quatre
  validacions de schema addicionals també passen (47 unitàries Zarr finals).
- `uv run coverage run -m pytest`: **932 passed**, sense skip ni xfail.
- Cobertura global: **96 %**, per sobre del llindar del 90 %.
- Proves noves: **47 unitàries Zarr + 13 d'integració**.
- Ruff check/format, Pyright, onze contractes d'importació, build i
  `git diff --check`: correctes.
- Smoke real: checkpoints 10/20, snapshots 5/10/15/20, verificació local correcta.
  Restaurar el checkpoint 10 i continuar fins al 20 coincideix amb el run continu.
- Dry-run: cap compilació ni stores; importar i executar el dry-run no carrega JAX.

Una passada completa inicial va avortar al compilador natiu XLA, sense assertions
fallides. La prova aïllada passa (10 proves). Els nous mòduls d'integració alliberen
les seves memòries cau de compilació en acabar; les dues passades globals posteriors
passen amb les opcions estàndard del compilador i sense desactivar cap prova.


Fora d'abast: PostgreSQL, MLflow, object storage, resume transaccional complet,
rollback, checkpoints incrementals, trajectories, accions/observacions i registre
analític de genomes. Un únic writer local per run. No es fa merge automàtic.
