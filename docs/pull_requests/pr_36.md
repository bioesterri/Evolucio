# PR-36 — Persistència Parquet de mètriques, naixements, morts i genealogia

Branca: `pr-36/parquet-telemetry-persistence`

Els runs registrats ara conserven la telemetria analítica en parts Parquet immutables
per chunk. Les mètriques es mostregen pel pas absolut (`step % metrics_interval == 0`);
naixements, morts i arestes genealògiques es capturen sempre. Cada birth genera una
aresta parent → child amb identitats, lineage, generation, genome IDs i resums de mutació.

La nova capa consumeix exclusivament DTOs host PR-31 i escriu DataFrames columnars
amb Polars natiu. Els esquemes v1 fixen ordre i tipus: String per run_id, Int64 per
IDs/passos/comptadors, Int32 per codis i Float32 per valors reals. Les causes de mort
es despleguen en columnes derivades del vocabulari real del projecte.

`artifacts/parquet/datasets.json` indexa parts, counts, rangs, mides i SHA-256.
El manifest PR-35 només referencia aquest índex. El runtime finalitza i verifica
Parquet abans de marcar completed; una fallada conserva els chunks confirmats,
registra complete=false i marca failed. La mateixa integració cobreix cada run
independent del batch PR-34.

Les parts i l'índex s'escriuen via temporal, tancament/sincronització i replace.
Un nom de part existent produeix error. Els readers retornen LazyFrames i només
consulten les parts indexades; les parts orfes es reporten sense adoptar-les.
`verify_local_run()` i la CLI existent incorporen hashes, esquemes, counts,
mostreig, identitats úniques, coherència births/genealogy i mort posterior al naixement.
`artifacts inspect` mostra counts, parts, interval i estat complete/partial.

Polars passa a dependència base amb el mateix rang ja declarat a l'extra analysis,
perquè la persistència és obligatòria en runs registrats. El lock actualitza Polars
a 1.44.2: la versió anterior 1.43.0 està retirada (yanked). No s'afegeix PyArrow.

La memòria del consumer conté dades d'un chunk i metadades de parts; no reté tots
els DTOs del run. Hi ha un sol writer síncron per run. No s'implementen SQL,
PostgreSQL, MLflow, Zarr, snapshots, genomes complets, checkpoints, resume, cloud
storage, compaction ni estadística científica.

Documentació: `docs/reference/parquet_persistence.md`.

Proves crítiques: reconstrucció E ← D ← B ← A; events als passos 3/7/11/18 amb
interval 10; equivalència de contingut amb chunks 4/7; fallada al tercer chunk;
fallada entre parts i commit d'índex; corrupció de bytes; readers buits; esquemes,
paths, causes, compressió i immutabilitat.

- `uv lock --check`: correcte.
- `uv run pytest`: **872 passed** (7 min 46 s), sense skip ni xfail.
- Proves Parquet: **32 unitàries + 4 d'integració**, correctes.
- `coverage run -m pytest` i passada complementària de proves Parquet finals:
  **97 % de cobertura global**, per sobre del llindar del 90 %.
- Ruff check/format, Pyright, 10 contractes d'importació, `uv pip check`, build i
  `git diff --check`: correctes.
- Smoke CLI real: 16 passos, chunks de 4; 16 metrics (steps 0–15), zero events
  en aquesta configuració, quatre readers consultables i verificació local correcta.
- Importar la capa Parquet no carrega JAX ni Equinox.
